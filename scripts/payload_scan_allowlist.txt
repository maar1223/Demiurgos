# Shared content-scan allow-list - SINGLE SOURCE OF TRUTH for both release
# gates. Consumed by scripts/secret_scan.sh (POSIX tree/CI scan and the
# POSIX payload audit) and by scripts/payload_audit.ps1 (the Windows package
# gate). Never duplicate this list in either script: the two ports once
# carried separate notions of "allow-listed" and the Windows gate rejected the
# shipped scanner's own rule literals while POSIX stayed green.
#
# Format: one repo-relative path per line. '#' starts a comment, blank lines
# are ignored. A path is allow-listed when it EQUALS an entry or ENDS WITH
# "/<entry>" (so absolute and root-relative paths match alike).
#
# What may be listed here - and nothing else:
#   * the scanner's own files: they contain the rule definitions by design,
#     so they necessarily match some patterns;
#   * obviously-fake test fixtures: placeholder values only, never real
#     credentials and never real author data;
#   * test harnesses that deliberately reference the patterns as functional
#     predicates (PATH scrubbing) or negative assertions;
#   * the two personal Google-Sheets tools (dev_diary.py, sync-ideas.py):
#     their only residual match is the required Sheets API parameter name
#     for the spreadsheet id; the real ids are read from environment
#     variables, never committed.
#
# No entry hides a real credential or a real author path: baseline violations
# must surface in tree/CI scans until their owning slice cleans them up.
#
# This file itself must stay clean - it carries paths only, and even its
# comments spell out rule names rather than rule literals, so it is NOT
# listed below.
