# Assistant response style: markdown, bounded length, one question

Objective: make the Demiurgos Assistant answer with restrained GitHub-flavored markdown, a bounded length, and exactly one question per turn. Fix the Hermes platform hint first (the system prompt is what forbids markdown), then the Demiurgos style contract, then the guided-flow convergence.
Branch: `feat/assistant-response-style`, based on `master`. Delivery: work-unit commits; no push/PR unless the Owner asks.
Runners: `.venv/bin/python -m pytest src/tools/demiurgos-suite/wiki/tests/`; `cd frontend && npx vitest run`; `cd frontend && npm run typecheck`.

## Specs

- **S1 (Owner authorization + style target).** "vamos con tu recomendacion en el orden correcto entonces"; accepted preview: "objetivo ~120 palabras, una pregunta, markdown moderado".
  Acceptance: every conversational answer targets 3–6 sentences (~120 words), with a soft ceiling of ~180 words. It expands only when the Author asks to explain, compare, inventory, or summarize. It never restates the whole conversation and never re-asks a resolved fact.
- **S2 (markdown).** "la ventana de chat está preparada para aceptar ese formato, pero el LLM no lo está enviando asi".
  Acceptance: the Assistant uses restrained GFM: `**bold**` for names and key terms, `- ` bullets only for inventories or steps, `##` headings only when there are three or more distinct sections. It never decorates a one- or two-line answer. The chat bubble already renders GFM (`AIAssistantSidebar.tsx` uses `MarkdownBody`).
- **S3 (length + one question).** "Responde con parrafos enormes y en ocasiones haciendo varias preguntas al mismo tiempo."
  Acceptance: exactly one question per turn on the `/ai/ask/activity` path. Alternatives are allowed but at most three, inline, inside that single question. No second question may appear in another paragraph. The rule is enforced by the prompt contract first; no post-processing that deletes Author-relevant content.
- **S4 (root cause: the system prompt).** The Hermes `api_server` platform hint hardcodes "assume plain text. No markdown formatting" (`agent/prompt_builder.py`, platform `api_server`), so any markdown request from the Demiurgos user prompt loses.
  Acceptance: the Demiurgos-owned Hermes profile declares `platform_hints.api_server.replace` (a `replace`, not `append`, because the prohibition is in the default text). The replacement keeps the plain-text file/media delivery rules and the brevity instruction. It is written by an idempotent YAML merge in `hermes_profile_config.py`, is exercised by provisioning, preserves unrelated keys, and never touches the personal `~/.hermes` profile.
- **S5 (guided flow).** The guided path keeps its own guarantees but must stop allowing walls of text and must converge.
  Acceptance: `SYNTHESIS_MAX_CHARS` drops to a value consistent with 1–3 sentences (~700 chars). The fixed conversation contract in `contract_projection.py` carries the convergence rule: when the method's anchors are covered and the Author is satisfied, summarize and offer the proposal; do not open new details unasked. `_guided_known_state` includes the finite plan progress (covered slots, next slot) so the provider knows how close it is to done.
- **S6 (evidence).** RED before each behavior rule; one regression test per existing behavior touched; full backend suite at closure. Live probe: after applying the config and restarting the gateway, a new session's stored system prompt carries the new `api_server` hint (no `No markdown formatting`).
