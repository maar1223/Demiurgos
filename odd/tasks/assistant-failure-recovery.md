# Assistant failure recovery and visibility

Branch: `feat/assistant-failure-recovery`, based on `master` after the `v0.2.7` hotfix.
Delivery: hotfix T1 as its own release slice; T2-T5 as one feature branch, work-unit commits: no push/PR unless the Owner asks.
Runners: `.venv/bin/python -m pytest src/tools/demiurgos-suite/wiki/tests/`; `cd frontend && npx vitest run`; `cd frontend && npm run typecheck`.

## Specs

- **S1** "ok pero el mismo error se ha repetido varias veces en varias sesiones seguidas." / "Como se puede solucionar definitivamente?"
  Acceptance: a durable guided or co-creation session is never owned by a per-login principal id. `create` stores the durable (`install:<install_id>`) binding, `recover` compares normalized bindings on both sides, and pre-fix rows are adopted on read with no schema change and no data migration. A live authenticated principal is still required on every route.
- **S2** "esto no debe pasar cuando el MVP esté totalmente en produccion"
  Acceptance: when the server reports that a session is gone (HTTP 401/409 on a guided continuation), the client drops the dead guided handle and its dependent state (pending proposal, consent token), shows one actionable message, and offers a new session. It never re-sends the same dead handle on the next message, and the blocked copy is never the only feedback for a recoverable state.
- **S3** "el mismo error se ha repetido varias veces" (same copy for unrelated causes)
  Acceptance: the user-visible outcome distinguishes at least: session expired/lost (recoverable), provider authentication failure, provider quota/balance exhausted, provider timeout, and invalid provider output. Each carries a different catalogue string and, where actionable, a next step. No provider or internal term reaches the UI.
- **S4** "no debe pasar" (fail-fast)
  Acceptance: a provider error the gateway classifies as non-retryable (HTTP 401/402/403/404 from the upstream provider) stops after one attempt instead of three; a bounded circuit breaker serves the specific failure copy for a short cool-down instead of retrying every turn. Retry stays bounded for genuinely transient failures.
- **S5** Evidence: RED before each behavior rule; one regression test per existing behavior touched; differential check for shared surfaces (assistant envelope, activity stream, guided continuation).
